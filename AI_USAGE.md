| 2026-09-28/c1c8247         | Claude | Review the sql schema I wrote explain unit_list, COLLATE NOCASE, ON DELETE CASCADE | Modified                                 | I wrote the schema, fixed int vs INTEGER PRIMARY KEY, IF NOT EXISTS, FK syntax, added RESTRICT                                      | In recipes.id it is INTEGER PRIMARY KEY so that every time a recipe is added the id also increments and each recipe has its own distinct id progressively. COLLATE NOCASE works so that when it comes to comparing the name of the ingredients the cases in their names don't affect comparison and thinks they are different ingredients (for example "flour" and "Flour" should be treated as the same), reducing redundancy. ON DELETE CASCADE works so that when a recipe is deleted all of the ingredients in recipe_ingredients that were related to that recipe_id get deleted as well so that the table doesn't have floating ingredients for recipes that no longer exist. Finally unit IN ('g', 'kg', 'ml', 'l', 'tsp', 'tbsp', 'pcs'): this ensures that the unit that is being added is accepted by sqlite3. This makes it easier for conversions because then conversions work in same families mass(g,kg), volume(ml, l, tsp, tbsp), and count(pcs). |
